# Choose a format, then load construction guidance

Honor an explicit viable format request. Otherwise choose the least complexity
sufficient to teach the point, not a default aesthetic or a table-size threshold.

| Reader need                                                                              | Format             | Construction reference                        |
| ---------------------------------------------------------------------------------------- | ------------------ | --------------------------------------------- |
| A direct fact, status, narrow source check, small decision or bounded comparison         | Plain text         | None                                          |
| A substantial report, connected explanation, self-paced evidence or interactive scenario | Reading-first HTML | [Visual Explainer](visual-explainer/SKILL.md) |
| An explicitly requested deck, converted slides, or a presenter-guided sequence           | Slides             | [Frontend Slides](frontend-slides/SKILL.md)   |
| A complete, always-running illustrative system-state diagram                             | Animated panel     | [live-panel](live-panel/SKILL.md)             |

Choose one primary format and load only its package. A short answer does not need
HTML just because it has several rows. A report can use a readable prose column
with figures; it need not become caption-only panels. Meaningful scenarios and
replays belong in reading-first HTML, not automatically in live-panel.

## Local boundaries override upstream routing

- Visual Explainer supplies reading-first HTML construction here. Its slide/video
  recipes are inactive for this workflow; Frontend Slides owns requested decks.
- Frontend Slides does not capture ordinary async reports merely because it can
  make reading decks. Use its reading-density variant only for an explicit deck.
  Reuse confirmed design preferences; ask only consequential missing questions.
  Style-preview exploration runs only when requested, not as a mandatory ceremony.
- live-panel is an illustrative always-running diagram, not an interactive story
  engine or real telemetry. Keep its simulation/source labels and full-frame view.
- Project design rules and confirmed owner preferences override package aesthetics.
  Do not install tools or assume an unavailable renderer succeeded. Use available
  construction paths and report blocked verification honestly.
- Publication remains with artifacts and owner-message delivery with
  active-telegram-message. Imported hosting/deployment recipes are inactive.
