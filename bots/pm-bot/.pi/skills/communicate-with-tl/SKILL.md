# Communicate with the Tech Lead

Start with the product outcome, current spec, and the technical answer needed. Budget means a useful scope boundary and accepted tradeoffs, not mandatory money or hour estimates. Ask TL to investigate evidence and recommend the smallest worthwhile achievement; PM owns the product decision under AGENTS.md.

## Workflow

1. Read the current feature artifacts and available findings. Frame a bounded assessment or next-action request, separating research from execution authorization.
2. Select one PM-authored message from the [template index](references/templates/index.md); read only that template and adapt its context, references, and JSON.
3. Send or reply through Agent Mail. Keep the request actionable and the expected response explicit.
4. Use the `project-management` skill when evaluating TL's response and deciding product scope or go/no-go. Use the `project-context` skill for managed document authoring, saving revised requirements or recording the decision through PM's available tools. Mail TL only when context, an answer, or a next action is needed.

These templates cover only PM → TL messages. Use the `project-management` skill for product decisions and the `project-context` skill for their persistence.
