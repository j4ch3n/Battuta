# Communicate with the Project Manager

Read named-spec metadata, the explicit current version, and product decision before affected work. TL owns technical findings, scope recommendations, and full canonical checklist/review writes. PM persists versioned documents and terminal go/no-go with rationale/hashes. Budget means scope alternatives and consequences, not mandatory cash or man-hour estimates.

## Workflow

1. Investigate the requested question using code, tests, documents, or a bounded probe. Separate observed/confirmed evidence from inference and unknowns.
2. Recommend a useful achievement milestone: what it accomplishes, what is deferred, and the consequences compared with broader alternatives.
3. Select one TL-authored message from the [template index](references/templates/index.md); read only the relevant example. Report a conclusion, focused clarification, honest progress, or evidence-backed result through Agent Mail.
4. Follow settled product scope from the explicit current version and propose technical plan/task content to PM. Use TL's tools for the single checklist/review and record actual assessed inputs. Reopen concerns only for material new evidence or a concrete blocker; terminal artifacts cannot be amended. No separate decision acknowledgment is required.

These templates cover only TL → PM messages. A completed assessment is not implemented work, product acceptance, or release.
