# FIS-151 Oracle Linux ARM64 Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development`
> or `executing-plans` to implement this plan task-by-task, after the human reviews
> this plan and selects execution. Steps use checkbox syntax for tracking.

**Goal:** Deliver a fresh-install Oracle Linux 9 ARM64 release with replaceable
compiled bot profiles, persistent private state, self-describing Python wheels,
and count-driven worker services.

**Architecture:** Build a bot-only archive from maintained sources, with per-role
instructions/skills and compiled extensions. Install locked JavaScript dependencies
under the selected installation and Python tools into uv environments; Pi uses
installed working directories with separate persistent agent directories. Share
current-state configuration and instance identity rules between setup and launch;
do not add migration paths.

**Tech Stack:** TypeScript/Node 24.21.0, pnpm 10.20.0, Pi 1.3.0, Python 3.12,
uv, Hatchling, systemd user services, tmux, GitHub Actions, Oracle Linux 9 ARM64.

**Spec:** [Approved design](../specs/2026-11-10-oracle-linux-arm64-release-design.md)

**Ticket:** [FIS-151](https://linear.app/fiscumco/issue/FIS-151), Todo.

`agent/fis-151-arm64-release`. Use this checkout, not another worktree. No runtime
implementation has started. Keep the ticket in Todo until execution is authorized.

## Global Constraints

- Fresh Battuta install on Oracle Linux 9 AArch64 with nvm and uv already set up.
- Node version comes from `.node-version` (currently `24.21.0`); pnpm version from
  root `package.json` (currently `10.20.0`). Runtime Python installation uses 3.12.
- Archive contains only `bots/`: generated `AGENTS.md`, complete selected skills,
  compiled runtime/resources, release metadata, and production dependency inputs.
- No bundled Node, dependency environments, runtime `skills-hub/`, credentials,
  TypeScript extension sources, or source-content-bearing maps.
- Python wheels carry exact runtime pins and same-release internal wheel URLs in
  `Requires-Dist`; no separate constraints or operator `--with` arguments.
- Persistent environment: `~/.battuta/.env.prod`. Private bot state:
  `~/.battuta/pi-bots/<bot>/.pi`. Never copy auth/models/sessions between bots.
- Preserve personal settings and state; regenerate owned configuration completely.
- `WORKER_BOT_COUNT` is required, non-negative decimal; zero means no workers.
- Production uses numbered services. Pi UI requires explicit foreground maintenance
  and a named instance; one bot per tmux pane, no simultaneous service/foreground use.
- No legacy detection/migration rules, automatic deletion/repair/rollback, live
  resizing, model calls, bot messages, provider login, or production mutations.
- Unit tests stub external/process boundaries and use package-local contract mocks.
  Reuse locked support projects; integration scripts are named `<subject>.it.py`.

## Review Focus

1. Path/identity confusion must not expose one bot's state to another, follow an
   unsafe symlink, or allow two processes for one identity (Tasks 1, 4, 5).
2. Private model settings and opaque auth/session files must survive configuration;
   generated files must not retain obsolete owned values or leak credentials (Task 3).
3. Moving compiled code must not break dynamic imports, prompt resources, native
   scheduler loading, Manager subagents, or worker-to-mail imports (Tasks 2, 8).
4. A wheel must install without sibling tools, editable sources, cached packages,
   constraints, or a post-build metadata rewrite hiding undeclared dependencies (Tasks 7, 8).
5. Missing counts, zero workers, nvm default changes, failed service stops, and tmux
   detach must not silently start work or start a second Pi process (Tasks 1, 4–6).
