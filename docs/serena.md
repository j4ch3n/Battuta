## Serena indexing

The directory index above is a navigation guide, not Serena's symbol cache. Serena uses [`.serena/project.yml`](../.serena/project.yml) for its language servers and indexing scope.

- Keep TypeScript and Python enabled for this mixed-language repository.
- Keep `ignore_all_files_in_gitignore: true`. Repository ignore rules already exclude nested `.venv/`, `node_modules/`, build output, and test caches; do not maintain duplicate exclusions in Serena.
- Keep the repository root as a workspace so all maintained components remain discoverable. The Python package roots are also registered as workspaces so Pyright loads their package-local settings. For a focused task, local overrides in `.serena/project.local.yml` can narrow `ls_workspace_folders` to the relevant component paths from the index above. Include callers and tests; omitted folders will not appear in Serena's symbol index.
- Serena ignore rules control its file selection, not every language server's import resolution or background analysis. Investigate the language server's project configuration separately if dependency analysis remains expensive.

With the Serena CLI available, run from the repository root to pre-cache symbols before the first broad symbol search:

```sh
serena project index
```

The command should exit successfully. Preserve the ignored `.serena/cache/` directory between sessions; regular usage updates the index as files change. Do not delete caches or run a full re-index before every task. Restart Serena after changing workspace or language-server configuration, then index the new scope as needed.

## Efficient navigation

1. Select the component using the project index above, then scope searches with `relative_path` rather than searching the whole repository by default.
2. Use `lsp.get_symbols_overview` to locate a file's symbols, then `lsp.find_symbol` to retrieve only the bodies needed. Avoid reading a whole file and subsequently fetching the same bodies again.
3. Use `lsp.find_referencing_symbols` to inspect callers. In TypeScript monorepos, cross-package results can be incomplete without suitable project references and source/declaration mappings; verify with a scoped text search before treating the result as exhaustive.
4. Use text search for configuration, documentation, or unknown symbol locations. Keep result sizes bounded and expand only when necessary.
5. When using Serena's REPL interface, batch independent operations in one call to reduce round trips. Batching does not make Serena execute language-server operations concurrently.

### Python environments

Each Python package's `pyproject.toml` configures Pyright to use its own `.venv` through `[tool.pyright]`. The relative `venvPath = "."` and `venv = ".venv"` settings avoid machine-specific interpreter paths. `pythonVersion = "3.12"` targets the packages' minimum supported Python version; the virtual environments themselves may use different supported versions. Selecting a venv supplies dependency search paths, but does not by itself select Pyright's target Python version.

These settings require separate package roots in Serena's `ls_workspace_folders`; a root-only workspace does not automatically load every nested package configuration. The root [Pyright configuration](../pyrightconfig.json) excludes those packages from the fallback workspace's background analysis to avoid scanning them twice. Those exclusions do not remove the packages from Serena's symbol index or their own Pyright workspaces. When adding a Python package, register its workspace, configure its local environment, and exclude it from the fallback Pyright scan.

For import-resolution issues, check the owning package's environment and source roots rather than selecting one package's virtual environment for the entire repository. Do not merge every environment's `site-packages` into shared search paths: that hides missing dependencies and mixes package versions. Restart Serena's language servers after changing these settings.

Serena filters declaration results inside ignored `.venv` directories even when Pyright correctly resolves the dependency. An empty dependency declaration result alone is therefore not proof of an unresolved import. Inspect Pyright's resolution/logs when validating the selected environment; keep dependency directories excluded from Serena's index.

Python reference searches can also be workspace-scoped: navigating from a consumer to another package's declaration does not guarantee that a reference search from that declaration includes the consumer. Cross-check callers with text search across package boundaries before refactoring.

Deno-specific resolution may need the Deno language server; do not enable it alongside TypeScript indiscriminately because both handle `.ts` files.

Before keeping a narrowed workspace configuration, check symbol lookup in each affected language and references across the changed package boundary. Restore the broader scope if callers or tests disappear. A smaller index is not an improvement if it hides code needed for safe changes.
