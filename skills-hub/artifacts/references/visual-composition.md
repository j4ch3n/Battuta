# Make the reasoning visible

Start the first viewport with the answer, not a decorative hero. Keep a readable
prose column, heading hierarchy, useful white space and restrained visual vocabulary.
Substantial text is appropriate when reasoning needs it; do not force everything
into cards, bullets or diagrams.

Give each figure one supported claim. Draw the mechanism rather than an empty
named box; label arrows with actions and boundaries with their meaning. Identify
units, dates, sources and uncertainty. Compare like with like using common scales.
Do not encode status by color alone. Inspect supplied images and preserve credits.

Base CSS owns reading layout. Each extension owns its scoped host/controls and
responsive treatment; copied styles are editable. Keep internal SVG/canvas sizing
intact. Reveal's embedded host needs a bounded height; use `embedded: true` so a
deck does not take over the document.

Slides carry one consequential point each. Use a readable claim, evidence and
transition; split overflow rather than shrinking text indefinitely. Inspect every
slide and print output. Phone and desktop screenshots reveal problems DOM checks
cannot establish away.
