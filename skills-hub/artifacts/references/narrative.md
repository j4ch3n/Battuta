# Build an explanation, not a topic inventory

Complete: “After reading this, the audience can explain ___.” Narrow it to one
useful insight. Begin with the reader's question and best-supported answer;
introduce actors and stakes before acronyms. A learning outcome needs no invented
recommendation or dramatic hook.

Outline the chain: question → takeaway → mechanism → evidence and alternatives →
implications and limits. Each section answers a question raised by the previous
one. Reorder research by this chain, not by which specialist produced it.
Takeaway headings state supported findings rather than generic topics.

Break complexity into an overview, one relationship at a time, then a concrete
example and its limits. Define terms at first use and keep one term per concept.
Prose supplies orientation and transitions; figures show a mechanism or comparison.
Use the same criteria and scales for alternatives. Put consequential caveats beside
the claim, with detailed methods at accessible depth.

Before: “Asynchronous validation with eventual persistence facilitates resilience.”

After: “The receiver saves the request before replying. A worker validates it
later. If that worker stops, it can retry the saved request. Whether that retry is
safe depends on whether repeating the action can create duplicate effects.”

This splits actors, sequence and the safety condition without claiming more than
the evidence. Source the mechanism before using this illustrative pattern as fact.
Never invent anecdotes, measurements, causal links or certainty for engagement.
Distinguish reported claims, observations, calculations, inference and simulation.
