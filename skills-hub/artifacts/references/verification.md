# Verify separate claims separately

- **Evidence:** inspect sources and recalculate important numbers. Keep uncertainty,
  competing explanations and limitations visible beside claims.
- **Understanding:** can the reader state the question, takeaway, mechanism and
  what would change the conclusion? Remove disconnected sections or add transitions.
- **Visual:** inspect actual phone/desktop renders, every slide, overflow, contrast,
  reading order, labels, fonts and print behavior. Source/DOM checks alone are not
  a visual pass. Report unavailable browser checks explicitly.
- **Behavior:** exercise controls, resets, backward/forward replay, multiple mounts,
  keyboard access, reduced motion, invalid/missing data and failed CDN loads.
  A model response or mock does not prove a real CDN integration works.
- **Sharing:** inspect `show` and the exact runtime allowlist. Keep private notes,
  map companions and notices private. Check intended images/modules/styles, not
  just HTML. Publication needs authority, not merely a ready draft.

Return the draft path, narrative/source decisions, checks and blockers to Manager.
After authorized publication inspect returned status/revision and local URL. A local
response does not prove external reachability or owner acceptance. Published edits
are live; recheck the changed version, not an older render.
