# Communicate with the Project Manager

Use the `project-context` skill when inspecting the current spec and product decision before affected work, or authoring the canonical checklist/review through TL's available tools. TL owns technical findings and scope recommendations; PM owns product decisions and versioned document persistence. Budget means scope alternatives and consequences, not mandatory cash or man-hour estimates.

## Workflow

1. Investigate the requested question using code, tests, documents, or a bounded probe. Separate observed/confirmed evidence from inference and unknowns.
2. Recommend a useful achievement milestone: what it accomplishes, what is deferred, and the consequences compared with broader alternatives.
3. Select one TL-authored message from the [template index](references/templates/index.md); read only the relevant example. Report a conclusion, focused clarification, honest progress, or evidence-backed result through Agent Mail.
4. Follow settled product scope from the explicit current version and propose technical plan/task content to PM. Use the `project-context` skill when recording assessment artifacts through TL's available tools. Reopen concerns only for material new evidence or a concrete blocker. No separate decision acknowledgment is required.

These templates cover only TL → PM messages. A completed assessment is not implemented work, product acceptance, or release.
